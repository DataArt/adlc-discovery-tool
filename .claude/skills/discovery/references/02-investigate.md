# Investigate session

Select work from the request and `01 Engagement/04 Where We Are/02 Investigate.md`.
Investigate repeats per domain and session until coverage is clear; it is not a
fixed-count workshop plan. Consult `01 Engagement/05 Workflows/03 Investigate/00
Orchestration.md` for the process definition when needed.

| Evidence or requested work                              | Reference                  |
| ------------------------------------------------------- | -------------------------- |
| Workshop preparation or source material to process      | [Capture](03-capture.md)   |
| Current State evidence affecting a domain               | [Domains](04-domains.md)   |
| Domain evidence supporting a root-cause hypothesis      | [Diagnose](05-diagnose.md) |
| Confirmed, stable Problem to ground in Strategic Intent | [Goals](06-goals.md)       |

Run the selected reference with the session subject and sources. If the request is
open-ended, recommend the next useful action from specific coverage gaps; ask for
missing source material or a consequential choice rather than a fixed menu.

A session may progress Capture → Domains → Diagnose → Goals when the evidence and
requested scope support it. Existing valid inputs permit starting later in the
chain. If new evidence invalidates an upstream claim, return to its originating
unit and revalidate affected downstream work. Each reference owns its reporting;
do not duplicate Report Log rows in this session controller.

Apply [coverage-check](../patterns/coverage-check.md) at session end. Return completed
work, remaining gaps, and the next eligible unit. In full-chain mode, clear coverage
permits Gate 1; direct Investigate entry ends with that recommendation.
