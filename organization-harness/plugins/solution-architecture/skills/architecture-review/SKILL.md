# Architecture Review

## Operating principles

Read [operating principles](references/operating-principles.md) before executing. This skill is a starter draft, not an approved organizational policy.

## Required context

Architecture documents, requirements, constraints and review scope.

## Workflow

1. Inventory available evidence and scope the review.
2. Assess requirements fit, security, reliability, operability and cost where relevant.
3. Record findings with evidence, impact and severity rationale.
4. Propose mitigations and questions; separate blockers from improvements.

## Expected output

Prioritized findings, evidence, recommendations and review limitations.

## Quality gate

Do not claim a security or compliance certification from a design review.

## Optional specialist delegation

When supported and appropriate, delegate independent assessments to security-architect, cloud-architect and data-architect. Confirm authorization and scope first; use generic subagents with equivalent role instructions or sequential assessments if custom agents are unavailable. Consolidate evidence and conflicting findings in the main session. Do not claim parallel execution if it did not occur. Human approval remains required for consequential decisions.
