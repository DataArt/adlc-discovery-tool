# Set up the Business Analysis plugin

Install **Business Analysis** from **Team Skills** in your host’s plugin marketplace. Open it in the workspace where you plan to use it and ask **“Run full setup.”** Have a representative project or meeting in mind so you can verify access to the sources you actually use. If you only want notes from a transcript or stories from a supplied brief, you can start by pasting that material into chat.

## First-time setup

1. **Connect your sources.** Onboarding walks through Atlassian, Zoom, Microsoft Teams, Outlook Email and Outlook Calendar one app at a time. Complete sign-in through the provider and return to chat. For Atlassian, identify both a Jira project and a Confluence space so each can be checked independently. Choose **Skip** to continue past an unavailable service. The readiness report records the gap.
2. **Choose specialists if you need them.** Ask to see the available roles. In a supported local Codex project, onboarding compares the selected definitions with the project’s `.codex/agents/` directory and previews additions or conflicts. Approve the changes you want, then confirm that the host discovers the installed roles. [Specialist setup](../skills/onboarding/references/agents.md)
3. **Preview a recurring job.** Choose a template below. Supply the scope, confirm the cadence and timezone, and request a read-only dry run. Review the proposed task, execution identity and result destination before approving its schedule. If your host lacks a scheduler, onboarding can give you the prompt and cadence for manual setup. [Job setup](../skills/onboarding/references/jobs.md)
4. **Read the readiness report.** Check which workflows can run and which sources were actually verified. A calendar event can be visible while its transcript is inaccessible. A successful interactive read also leaves scheduled access unverified until the scheduled identity has been tested. You can return later with **“Resume setup”** or **“Recheck Jira for this project.”**

| Job                                                                   | Default schedule                                 | What to configure                                                                                                                                                                                       |
| --------------------------------------------------------------------- | ------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| [Daily meeting notes](../jobs/daily-meeting-notes.json)               | Daily at 18:00, Europe/Madrid                    | Select an Outlook calendar, Teams chats or channels, meeting filter and time window. Add Zoom if useful. Name the reviewer, private review destination, and intended Confluence site, space and parent. |
| [Hourly Zoom meeting notes](../jobs/hourly-zoom-meeting-notes.json)   | Hourly, at least 15 minutes after each call ends | Configure the project context, eligible calendar events, Zoom audio and transcript access, BA or PM reviewer, Confluence destination and Outlook mailbox for reply drafts.                              |
| [Weekly requirements review](../jobs/weekly-requirements-review.json) | Mondays at 10:00, Europe/Madrid                  | Select the Jira project, Confluence space, reporting window and result destination. Check that both sources are readable by the scheduled identity.                                                     |

The daily job ends with private drafts. To publish one, the designated reviewer inspects its full text, revision and destination, then explicitly approves that item in interactive chat. If the reviewer requests edits, the revised draft goes back for approval. [Meeting-notes review and publication](../skills/meeting-notes/references/meeting-job.md)
