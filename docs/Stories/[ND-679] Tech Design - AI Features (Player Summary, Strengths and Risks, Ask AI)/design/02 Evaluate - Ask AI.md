# ND-679: Ask Magpie — Evaluate

_Produced by the Evaluate phase._

Decision 5 recommends Option B: a new sibling Azure Container App, shared across Decisions 1, 2, and 3's generation needs. Decision 6 recommends Option A: LangGraph (TypeScript), driven significantly by Ask Magpie's own requirement for cross-turn conversational memory, which LangGraph's checkpointer provides off the shelf. Research's Option E for this decision (LangGraph `StateGraph`) matches both Decision 5 and Decision 6. Option E runs _inside_ Decision 5's existing shared Container App deployment, not a second, separate new Container App: one shared substrate already serves Decisions 1, 2, and 3's agent needs, and Option E reuses it rather than adding a second. All five options, A through E, are scored below.

## Recommendation

**Recommended option: Option E — LangGraph `StateGraph`**, running inside Decision 5's shared Container App deployment, not Option D's hand-rolled router.

Option D is the strongest hand-rolled shape and a close second choice. Decision 6's recommendation (LangGraph) is driven specifically by Ask Magpie's requirement for cross-turn conversational memory — the one capability no hand-rolled option (A through D) provides without a bespoke, unverified memory layer. With the framework fixed as LangGraph, declining to use it for the one feature whose own requirements justified choosing it would mean building and maintaining a second, parallel memory mechanism alongside the framework the team is already committed to operating. Option E is also the only option that resolves "how to combine answers that span multiple capabilities" by construction, via a named `synthesize` node, rather than leaving it as an open design question deferred to Solution (D's own gap, see OQ-1 below). Option A is excluded outright: it requires "a new sibling container (own deployable)," which contradicts Decision 5's choice to reuse the shared deployment. Options B and C are workable but lose the clean per-domain permission scoping that D and E get for free, a material gap given this feature surfaces medical- and scouting-adjacent data through its profiles.

Option E runs _inside_ Decision 5's shared Container App deployment, not a second, separate new Container App: one shared substrate already serves Decisions 1, 2, and 3's agent needs, and Option E reuses it rather than adding a second. Its router-plus-capability-node topology is structurally the same shape as Option D's router-plus-profile-bundle, expressed as a graph instead of a hand-rolled dispatch, so the two options carry comparable integration risk apart from the new framework idioms.

The build/operate cost tradeoff is the honest cost of this recommendation: Option E scores 0.65/warn on that row versus Option D's 0.85/check, since LangGraph brings the heaviest dependency tree and a checkpointer schema to maintain. That cost is accepted here because it buys the one requirement (built-in cross-turn memory) that a hand-rolled option cannot match without equivalent or greater bespoke effort, and because Decision 6 has already committed the platform to operating LangGraph for other features — this is not a cost paid solely by Ask Magpie.
