# Requirements Analysis

## Operating principles

Read [operating principles](references/operating-principles.md) before executing. This skill is a starter draft, not an approved organizational policy.

## Required context

Requirements, stakeholder objectives and available system context.

## Workflow

1. Inventory and identify requirements; preserve source references.
2. Separate functional and non-functional requirements and constraints.
3. Identify conflicts, ambiguities and gaps; formulate targeted questions.
4. Draft a prioritized requirements baseline with assumptions explicitly marked.

## Expected output

Requirements matrix, assumptions, gaps and clarification questions.

## Quality gate

Do not treat inferred requirements as approved scope.

## Optional specialist review

When independent assessments are appropriate and authorized, use the [business analyst](../../agents/business-analyst.toml) for actors, outcomes and missing requirements, and the [requirements reviewer](../../agents/requirements-reviewer.toml) for traceability and testability. If the host lacks registered agents, apply the roles sequentially or use authorized generic delegation. Describe how the review ran, reconcile conflicting findings against the sources and leave scope decisions to the user.
