# Patch 0035 — contribution-github-setup

## Summary

Managers were getting stuck at the very first step of the Claude/Codex Desktop onboarding — cloning the repo — with no terminal experience and, in practice, HTTPS password/PAT auth failing outright (GitHub deprecated password auth; org policy blocked PATs; SSH was the only thing that actually worked). This bundle reworks the Contribution setup flow around that reality:

- New page **GitHub Repo Setup** walks through two no-assumptions paths: **GitHub Desktop** (point-and-click, including the "Code → Open with GitHub Desktop" button on the repo page itself — no manual URL pasting) and **Terminal/SSH** (SSH key generation, since HTTPS password/PAT auth is unreliable in practice), plus a troubleshooting table built from a real failure encountered mid-session (`403 Write access to repository not granted` → actually a stale-credential problem, resolved by switching to SSH).
- **Claude Desktop Setup** and **Codex Desktop Setup** step 1 no longer inline a `git clone` command — they just point to GitHub Repo Setup (Option A) for the no-terminal path.
- Both setup pages now have the assistant run the environment setup script itself (`Run scripts/setup/setup.sh to set up this project.`) instead of instructing the manager to open a separate terminal — via a new single-entry-point **`scripts/setup/setup.sh`** dispatcher that detects the OS (`uname -s`) and hands off to the right platform script, so the prompt never has to guess which script applies. Windows gets a new **`scripts/setup/setup-windows.sh`** — Claude/Codex Desktop's shell tool on Windows runs through Git Bash, not PowerShell directly, so this is a thin bash wrapper that hands off to the existing `setup-windows.ps1` (path-translated via `cygpath`) rather than duplicating its install logic.
- **Codex Desktop Setup** step 2 was rewritten from a guessed generic "Open folder" flow to the actual UI: switch the app's ChatGPT/Codex dropdown, click **+** next to **Projects**, fill in the **Create project** dialog (name + source folder) — with real screenshots. Two more screenshots illustrate the "free-form status prompt" and "run the site / live preview" rows in the Contribution guide table.
- `07 Contribution/04 Branching Policy.md` → `05 Branching Policy.md` and `05 Quick Walkthrough.md` → `06 Quick Walkthrough.md`, renumbered to make room for the new `04 GitHub Repo Setup.md`; the Engagement `index.md` table updated to match.
- Both setup pages' Prerequisites sections now also say: once you have a GitHub account, share your username with the engagement lead/repo admin so they can grant repo access — cloning fails regardless of method without it.
