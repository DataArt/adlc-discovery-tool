# Discovery evidence interface

Use when updating Current State, SDLC Domains, Problems, Claims, the Where Gaps Sit
heatmap, or Solution Goals. Preserve existing IDs, links, registry fields, and
Changelog history; adapt narrative composition to the evidence.

- Current State describes observed practice with specific workshop/source citations.
- SDLC Domains explain what that practice means for a domain, tracing back to
  Current State and the originating session.
- Problems state a root cause and delivery impact, name the affected delivery stages,
  and link specific domains and supporting sources. Apply the status ladder in
  `references/05-diagnose.md`; narrative confidence cannot replace corroboration.
- Claims contain verbatim source quotes, the Problem ID, and the specific workshop.
  Preserve the append-only ledger and never reuse retracted Problem IDs.
- The heatmap reflects the current Problems and Claims, including retractions,
  rather than introducing independent diagnostic assertions.
- Early Solution Goals link a confirmed, stable Problem and matching Strategic
  Intent. Clearly distinguish a draft goal from Gate 1's prioritised approval.

## What good looks like

A reviewer can follow Goal → Problem → Domain → Current State → workshop evidence
and independently check each status. Separate observation, interpretation, and
unresolved questions. Choose tables, narrative, or diagrams for clarity while
retaining the registry contracts consumed by coverage and gate checks.
