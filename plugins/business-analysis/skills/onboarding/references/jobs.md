# Set up a recurring job

Select the requested template. During full onboarding offer the available jobs and let the user select or skip each one. For overlapping meeting filters, agree which job owns each occurrence. Configure each selected job separately.

| Template                                                                    | Inputs and procedure                                                                                                                                                                                                                                                                   |
| --------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| [Weekly requirements review](../../../jobs/weekly-requirements-review.json) | Resolve the Jira project, Confluence space, reporting window and scheduler result destination. Use [requirements analysis](../../requirements-analysis/SKILL.md).                                                                                                                      |
| [Daily meeting notes](../../../jobs/daily-meeting-notes.json)               | Bind the calendar, Teams chats/channels, optional Zoom scope, meeting filter, reporting window, reviewer, private result destination and intended Confluence site, space and parent. Use the [meeting interfaces and review procedure](../../meeting-notes/references/meeting-job.md). |
| [Hourly Zoom meeting notes](../../../jobs/hourly-zoom-meeting-notes.json)   | Configure project context, calendar selection, Zoom evidence, BA or PM review chat, Confluence parent and Outlook sender mailbox using the [Zoom meeting procedure](../../meeting-notes/references/zoom-meeting-notes.md).                                                             |

1. For a preview, describe the selected template's prompt, inputs and default schedule.
2. For setup, resolve the selected template’s inputs and execution identity. Confirm cadence, timezone and notifications. Choose a destination compatible with read-only execution, such as the scheduler's own result view.
3. Inspect scheduler capabilities and existing tasks for this template, owner and project. Check the scheduler’s support for standalone runs, the skill and selected sources under the intended identity. Where only interactive access can be tested, record scheduled access as unverified. If a local machine is needed, state its availability requirements. Identify any unsupported settings.
4. Dry-run the selected job with scoped read-only access where feasible. Identify any unverified prerequisites. Bind the agreed inputs into the durable prompt. For meeting notes, include the read-only discovery, deduplication and private review handoff instructions. Confirm the reviewer can retrieve the exact draft across sessions. If the scheduler cannot load the packaged skill, include the instructions needed for the selected job directly in the prompt. Preserve the template's evidence requirements, per-run access checks and external-write restriction.
5. Show the exact durable prompt, scope, schedule, timezone, destination and notification behavior. Create or update a matching task only with approval of the proposal. Resolve uncertain matches before creating another task.
6. Read back the task ID and settings when the scheduler supports it, and identify how to pause or change it. If scheduling is unavailable, return the copyable prompt and schedule with manual setup instructions. Report dry-run and registration status separately.
