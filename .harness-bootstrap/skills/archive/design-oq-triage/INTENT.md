## Purpose

A reference rule for classifying open questions (OQs) that surface during the Research phase of a design lifecycle. Defines two tiers — Viability `(V)` and Elaboration-input `(E)` — and specifies when each must be resolved. Referenced by `design-research` (Step 3b) and `design-elaborate` (Step 1b).

## Substitutions

None. This skill has no project-specific values — the protocol is generic across all design lifecycles.

## Conditionals

None.

## Verify checklist

- [ ] Two-tier table present: `(V)` Viability and `(E)` Elaboration-input with definitions
- [ ] Rule 1: OQ classification happens at end of Research Step 3 (after options confirmed)
- [ ] Rule 2: `(V)` OQs resolved before saving `01 Research.md`
- [ ] Rule 3: Elaborate Step 1b re-checks unresolved `(V)` OQs
- [ ] Rule 4: Solution re-checks and creates spike tickets for unresolved `(V)` OQs
- [ ] Rule 5: `(E)` OQs captured with `(E)` prefix in Research.md
- [ ] Why section explains the rework risk (no project names needed)
