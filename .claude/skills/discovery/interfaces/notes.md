# Session notes interface

Use for workshop or gate `Notes.md`. Identify the actual session and source
transcript or written notes; include duration and start time only when known.
Map the discussion to agenda topics/blocks in chronological order. For each reached
question, state the evidence-supported answer and useful context. Mark unreached
questions as carry-forwards instead of inventing answers.

Keep a Topic Coverage table for workshops or Block Coverage table for gates:
🟢 fully covered, 🟡 partially covered, 🔵 surface-level only, ⚫ not reached.
These describe discussion coverage, not Problem status or stakeholder approval.

Capture concrete numbers with their units and significance when present, synthesize
key themes, and distinguish facilitator observations from participant evidence.
Preserve exact quoted text as `_"..."_`; use organizational roles rather than names
in workshop synthesis and expand abbreviations on first use. Use the actual workshop
name. For gates, capture the response to each explicit ask and evidence of decisions,
caveats, or flags. Link carry-forwards to an owner and next step where known.

## What good looks like

A reader can trace a summary or quotation to the specific session source and tell
what was established, left uncertain, or not discussed. Use headings, tables, or
short narratives as needed; colored HTML panels and empty metric sections are not
required. Notes faithfully capture the session; diagnosis remains a separate stage.
