# Zoom meeting notes

Use this procedure for hourly Outlook calendar checks and manual requests for notes from Zoom recordings. It specifies the evidence, draft format and Outlook handoff for this workflow. Use the [publication procedure](meeting-job.md) for revision-specific approval, Confluence checks and recovery from uncertain writes.

## Set up the project and sources

On `Start setup` (case-insensitive), follow the [guided setup](zoom-setup.md) in the current chat. Start with the setup scope and ask only for missing or unclear settings.

## Collect and verify evidence

- Every hour, apply the configured event filter. An occurrence first qualifies when its scheduled end time plus 15 minutes falls at or before the check. Cover the interval since the last successful check, including meetings still awaiting assets. Persist discovery, review revision, publication and Outlook draft status per occurrence in the configured workspace. Reconcile existing outputs before resuming. If already processed, report the existing status. If prior state cannot be determined, resolve the possible duplicate with the reviewer.
- Read the title, date, start time, timezone, original invitees and Zoom link from the event. Match the exact occurrence using the Zoom details and occurrence time. Notify the reviewer immediately if the link is missing. Ask which link to use if there are multiple candidates. Leave recurring calls with a shared Zoom link unresolved until the matching rule is confirmed. Treat any Outlook Mail fallback for Zoom notifications as unverified until tested. Verify the call has ended. Listen to the recording and correct only words, figures or speakers supported by the audio. A recording URL alone does not establish that audio was checked.
- Follow the [edge case rules](#edge-cases) for retryable failures and incomplete material. Report when the host cannot schedule retries.
- For a manual request, start from the supplied link, recording or transcript. An Outlook event is optional. Ask for missing details or usable material as needed. Transcribe a recording when supported. With only a transcript, ask whether to proceed using it as supplied. Disclose the evidence actually used.

## Prepare one draft for the occurrence

Write headings, notes and clarification questions in concise business English regardless of call language. When earlier notes or transcripts are available, identify prior context and explain what changed or remained open in the current call. Preserve official names and identifiers. Identify the call in chat by title, date, start time and timezone, and include verified direct resource links where available.

Use these header fields in order **Meeting title**, **Participants invited** (original Outlook invitation), **Actual participants** (attendance confirmed by Zoom attendance records or the reviewer), **Meeting date** (with start time and timezone), **Notes by** (identified notes author), and **Sources**. Include **Meeting files** as a two-column table with columns **File** and **Link / details**. Add a **Video / recording** row with the shareable Zoom recording link when available. Add a **Recording password** row only if it was provided for sharing with the intended audience.

Group **Topics Discussed** by topic, identifying the project where useful. Capture stated business needs, expected system behavior, scope, constraints and dependencies. Distinguish proposals, confirmed decisions and open questions. Follow with **Decisions made** and their conditions, **Open questions**, and **Follow-ups/Action points** with agreed next steps, owners and deadlines. Include agreed inputs or dependencies needed to answer open questions. Preserve relative deadlines as stated. Apply the [edge case rules](#edge-cases) for unconfirmed assignments and conflicting evidence. Use “Not specified” for missing fields and “None recorded” for empty sections. Keep all projects discussed in the same set of notes.

Use the [review message examples](review-messages.md) for draft delivery, clarifications and status updates. Below the proposed page body, show **Uncertainties to clarify** in a separate private reviewer block. Explain each ambiguity and ask a specific question about unclear decisions, owners, deadlines, conflicting prior notes or evidence gaps. Apply confirmed answers to the draft and present the revised version. If uncertainty remains, ask whether the reviewer wants to finalize with those points unresolved. Keep unconfirmed outcomes out of decisions.

## Publish, then prepare the reply

Show the BA or PM the exact revision, [Confluence page title and body](confluence-page.md), destination and proposed follow-up. Resolve ambiguous approval by confirming the revision or wording before publication. On explicit approval in chat, follow the [publication procedure](meeting-job.md) to publish and verify the page. After verified publication, use the [Outlook reply procedure](outlook-reply.md) if the original invitation is available.

Return the Confluence link and the Outlook draft status or link. Report confirmed differences between invitees and attendees in chat. For a manual call without an invitation, finish with the page link. If reply draft creation fails, is unsupported or its save is uncertain, report the specific issue alongside the published page link and check for an existing draft before retrying. Resume at the unfinished handoff when the page is already verified.

## Edge cases

Identify the call by title, date, start time and timezone in reviewer notifications. Include verified direct resource links where appropriate. Use these rules alongside the [publication procedure](meeting-job.md). An identical page verified by read-back can be reused for the remaining handoff.

| Situation | What to do |
| --- | --- |
| The hourly calendar check does not start or Outlook Calendar is unavailable | Retry the calendar check up to three times, at 15, 30, and 45 minutes after the scheduled check. Stop retrying as soon as calendar access succeeds and continue the workflow. If all three retries fail, notify the BA or PM in chat that the tool could not access Outlook Calendar. |
| The calendar event has ended, but the Zoom meeting is still in progress, was canceled, or no matching meeting is found | Check Zoom up to three more times, at 15, 30, and 45 minutes after the initial Zoom check. Continue the workflow as soon as the matching meeting is found and confirmed to have ended. If the issue persists after the third retry, notify the BA or PM in chat with the meeting title and the specific issue observed. |
| The calendar event cannot be identified | Ask the BA or PM to identify the event. |
| The calendar event has no Zoom link | Immediately notify the BA or PM in chat that meeting notes cannot be generated for the named calendar event because its Zoom link is missing. Stop processing the event. |
| The calendar event contains several possible Zoom links | Ask the BA or PM which link belongs to the meeting before retrieving Zoom materials. |
| Multiple meeting occurrences use the same Zoom link | Flag the shared link in chat and pause the occurrence until the matching rule is confirmed. The link may lead to another occurrence’s files. |
| Zoom is still preparing the recording, the transcript, or both | Check Zoom up to three more times, at 15, 30, and 45 minutes after the initial check. Stop retrying when both files are available. If either file is still unavailable after the third retry, notify the BA or PM in chat with the meeting title and specify which files are missing. |
| Only the Zoom recording or transcript is available, neither is available, or a file exists but cannot be accessed | Retry up to three times, at 15, 30, and 45 minutes after the initial check. Continue processing as soon as both files are accessible. If the issue persists after the third retry, notify the BA or PM in chat with the meeting title and specify which files are missing or inaccessible. |
| The Zoom recording or transcript covers only part of the call | Immediately notify the BA or PM in chat, identify the call and the incomplete material, and ask whether to draft notes from the available material or stop processing the call. Wait for explicit direction before generating any notes. If the reviewer asks for a draft, use the available material and flag gaps that affect the notes. If the reviewer asks to stop, close the case without generating notes. |
| A speaker, deadline, or outcome remains unclear after checking the recording | Under **Uncertainties to clarify**, identify the relevant point, explain what remains unclear after checking the audio, and ask the reviewer to confirm the specific detail. |
| A long discussion ends without a recorded decision or agreed action | Summarize the discussion briefly and use “None recorded” where applicable. Under **Uncertainties to clarify**, explain that no outcome was captured and ask the reviewer to confirm whether the topic remained unresolved. |
| An agreed action has no confirmed owner or deadline | Use “Not specified” for the missing field. Under **Uncertainties to clarify**, identify the action, explain which detail was not confirmed, and ask the reviewer whether an owner or deadline was agreed. If someone is asked to contact an absent colleague, keep the person making the contact as the owner and list the colleague as the contact. If the group expressly assigned the work to an absent person, record that assignment without implying they accepted it. |
| The current call conflicts with earlier notes and does not explicitly change a prior decision | Under **Uncertainties to clarify**, summarize the earlier decision and the conflicting point from the current call. Ask the reviewer whether the earlier decision still applies or was superseded. |
| The BA or PM does not answer the clarification questions or answers only some of them | Apply any answers received. List the remaining uncertainties in chat and ask whether the reviewer is comfortable finalizing the meeting notes without resolving them. Wait for explicit confirmation before omitting them from the final notes. Keep any affected outcomes unconfirmed. |
| Multiple draft versions exist and it is unclear which version or decision wording the reviewer approved | Immediately add an item under **Uncertainties to clarify**. Identify the competing versions or wordings and ask the BA or PM which one to use. For an affected topic, note that it was discussed under **Topics Discussed** and mark its outcome as `TBD decision`. Once the reviewer clarifies, update the meeting notes, replace the placeholder with the confirmed outcome where applicable, and remove the resolved uncertainty. |
| A scheduled check finds an existing draft, review, published page or Outlook draft | Immediately notify the BA or PM in chat with the meeting title and its current status. Keep the existing notes and avoid creating a duplicate Confluence page or Outlook draft. |
| The Confluence destination is missing, access is denied, or an existing page conflicts with the approved notes | Immediately tell the BA or PM in chat that the notes for the named meeting could not be published. Explain the specific issue, ask for help, and wait for the reviewer to resolve it or tell the tool how to proceed. |
| Confluence returns an error or does not confirm whether publication succeeded | Immediately tell the BA or PM in chat that publication for the named meeting failed or could not be confirmed. Include the error or observed issue, ask for help, and wait for direction. If the result is uncertain, verify whether a page already exists before any retry. |
| After successful Confluence publication, Outlook cannot create the reply draft, link it to the original calendar event, or confirm that it was saved | Notify the BA or PM in chat with the meeting title and the specific Outlook issue. Include the published Confluence page link. If saving could not be confirmed, report the draft status as unconfirmed. |
| The original Outlook invitation list differs from actual Zoom attendance | Address the reply draft to everyone on the original Outlook invitation list. In the draft-created chat notification, list invitees who did not attend and attendees who were not invited, when confirmed. Leave any recipient changes to the BA or PM. |
