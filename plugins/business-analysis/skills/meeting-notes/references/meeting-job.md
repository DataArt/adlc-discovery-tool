# Meeting discovery, review and publication

## Interfaces

These are capability contracts. Resolve the actual operations exposed by the connected host for the selected account. During setup, verify the scheduler can read the configured sources and deliver a private result the reviewer can open. Verify the interactive host separately for publication.

| Interface                                              | Inputs                                                                                               | Operation and result                                                                                                                                                                                                                       |
| ------------------------------------------------------ | ---------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Outlook Calendar · discovery                           | Calendar ID, start and end with timezone, meeting filter                                             | List event occurrences in the window, including recurring instances. Collect occurrence ID, actual start/end, cancellation status, subject and meeting link.                                                                               |
| Microsoft Teams · messenger discovery and evidence     | Selected chats or channels, window, meeting filter                                                   | Search scoped messages for meeting references and follow-ups, including meetings absent from the calendar. Read matched threads for attributable discussion. Retain thread/message links and timestamps.                                   |
| Zoom · optional Team Chat or meeting evidence          | Selected chat scopes or matched meeting occurrence                                                   | When configured and supported, search Zoom Team Chat within scope. For a linked Zoom meeting, read available notes, transcript or summary for that instance. Record the asset type and source link.                                        |
| Private review · scheduler result and interactive chat | Reviewer, occurrence key, draft revision, full title and body, sources, Confluence site/space/parent | Deliver one reviewable item per meeting. Accept approve, request edits or skip for identified items. If the result view cannot take replies, the reviewer can bring the item into an interactive chat with the plugin.                     |
| Confluence · interactive publication via Atlassian     | Approved item, destination IDs and reviewer authorization                                            | Read target and space authoring guidance, search for a prior page, create a page and read it back. Use the host's Confluence search, create-content and get-content interfaces. Return the verified URL or the precise outstanding status. |

## Scheduled run

Search calendar and messenger scopes independently and follow pagination for the configured window. Mark any incomplete search. Exclude cancelled and future meetings. Match cross-source records using an occurrence ID or meeting link plus date and time. For chat-only meetings, use a stable thread/message link and occurrence time. Keep recurring sessions distinct. Flag ambiguous matches for the reviewer.

Use meeting discussion, notes or transcript as evidence for the [meeting-notes workflow](../SKILL.md). An invitation, agenda or join link alone identifies a candidate. List candidates without usable evidence as waiting for notes. Present each draft in the private review destination. Include its occurrence key in the proposed page body as a source reference, plus the full proposed title, destination, revision, and coverage gaps. If nothing qualifies, summarize the searched window and coverage. End the scheduled run before publication.

## After review

1. In an interactive session, resolve the reviewed item and verify that the responding user is the configured reviewer. If identity, revision, full text or destination is ambiguous, resolve it before publishing. Approval must explicitly cover the displayed revision and destination for each selected meeting. Setup consent, silence and earlier approvals do not carry forward.
2. Apply requested edits in the private draft. Show the revised text and destination for fresh approval after any change. Leave skipped or pending items private.
3. On approval, check the intended parent in the specified site and space, load the connector's required format and space guidance, and search for the occurrence key. If applying guidance would change the reviewed content or location, present the change for approval. If an identical page already exists, return its link. If a different page matches, show the conflict for review.
4. Create the approved page once under the confirmed parent. Verify the resulting page, location and content by read-back. After an uncertain write or retry, reconcile against the returned ID or occurrence key before another create. If the outcome is ambiguous or access fails, keep the draft and report what remains unresolved.
